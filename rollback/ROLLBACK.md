# 回退方案：不得损坏现有游戏与存档（任务书 §13-10）

## 原则

1. **原件只读**：任何工具都不覆盖输入文件。`tools/native/iostore.py`、`inplace_patch.py` 在写入前都会检查输出目录不是输入目录、不是非空目录，否则拒绝执行（有测试覆盖）。`tools/data/player_appearance.py` 写的是单个文件而不是目录：`--out` 和旁边的 `<out>.patch.json` 都不能是任何输入文件（整表、单条记录、encode 的 JSON、`--set-json`，含符号链接/硬链接），已存在时必须加 `--overwrite`；`decode --out` 同样不能覆盖输入或已有的原始记录备份（有测试覆盖，`tools/tests/test_player_appearance_adversarial.py`）。
2. **每次写入都有清单**：输出目录里有 `manifest.json`（外观编解码器是 `<out>.patch.json`），记录每个输入/输出文件的 SHA-256、改了哪些 chunk/字段。回退就是"把清单里列出的输出文件换回清单里记录哈希的原件"。
3. **先备份再安装**：装测试包前，先把下面三类东西完整备份，并核对哈希：
   - 原版 IPA（或已安装 App 的完整导出）；
   - 游戏下载数据目录里被替换的容器文件（`.utoc/.ucas/.pak` 原件）；
   - 本地存档与主控项目的球员/卡片数据库文件。
4. **新内容和原内容分开**：大罗的数据以"新增记录 / 新资源包"的形式提供，不改动其他球员的记录和共享资源（独立绑定落地前，原位替换方案只能在隔离的测试客户端里使用）。

## 回退步骤

| 场景 | 操作 | 校验 |
|---|---|---|
| 测试包装上后游戏崩溃或进不了比赛 | 删除测试包，重新安装备份的原版 IPA；把备份的容器文件放回原位置 | 对照备份清单逐个比对 SHA-256 |
| 只有资源出错（脸/贴图异常，其他正常） | 用 `manifest.json` 中记录的原件替换被修改的 `.utoc/.ucas` | `python3 tools/native/iostore.py hash-all <容器>` 与备份时的哈希表 `diff` 为空 |
| 数据出错（能力、技能、成长异常） | 主控 Claude 撤回大罗那条记录的导入（数据以独立文件导入，不改动其他卡） | 抽查 3 名其他球员的能力与修改前一致 |
| 存档读不出 | 恢复备份的存档文件 | 能正常进入阵容页面、其他球员等级与经验不变 |
| 其他球员外貌变了 | 说明误用了共享资源替换。立即回退资源文件，改用独立绑定方案 | 对照修改前截图检查 3 名共用该资源的球员 |

## 主控集成时的数据安全要求（交给主控 Claude）

- 导入前先查 `card_id 88044146203441`：存在则**更新该记录**（先导出原记录备份），不存在才新增；不得出现两张 2002 大罗实例。
- 不改卡池、经济、奖励、T0 资格（任务书 §14）。
- 导入脚本必须可重复执行（幂等），并提供撤销脚本。
