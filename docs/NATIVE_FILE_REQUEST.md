> 目的：完成原生资源适配、独立球员绑定与实机测试包。没有这些文件，原生接入的任何一步都不能声称完成（任务书 §7、§12）。
> 写于 2026-10-25。按优先级排列；**A 组齐了就能开工**，B、C 组可以后补。

## 0. 上传前必读（安全与版权）

1. **本仓库 `guedonald87864-lab/wdxac` 目前是公开仓库（public）。** 游戏文件是 Konami 的版权内容，**绝不能**上传到公开仓库。
   - 推荐做法：在 GitHub 把仓库改为 Private（Settings → General → Danger Zone → Change visibility），或者新建一个私有仓库专门放原始文件，然后告诉我仓库名，我用 `add_repo` 接入。
   - 大文件（> 100 MB）请用 Git LFS，或拆分后上传；也可以只先传 A 组里的小文件。
2. **不要上传任何密钥、账号、密码、证书私钥。** 如果容器是 AES 加密的，请在你本机用已有工具（Codex 当时用的方法）先解密/导出，再上传解密后的数据；或者在你本机运行我们的 `tools/native/iostore.py --aes-key-file`（密钥只留在你电脑上）。
3. 所有改动只用于你的本地单机构建。研究笔记 05 §5.3 记录了 Konami 把修改游戏数据列为违规行为，不要接入官方在线服务。

## 拿到 A 组后我会做什么（按顺序）

1. 核验版本、容器版本、压缩方式（Oodle/zlib/LZ4/不压缩）、加密标志；对 `.utoc` 做"解析→重新序列化"字节级一致性自检。
2. 用 A3 的供体数据（或从 B1 里重新提取）建立供体网格/贴图的基线，回读校验。
3. 用 `tools/wrap/` 把 R9 头型包裹到供体拓扑上（保持顶点数、顶点顺序、UV、骨骼与权重不变），生成两级 LOD 与 256 px ASTC 贴图。
4. 生成两种候选：
   - **测试候选**：原位替换供体资源（只在隔离的测试客户端里用，**会影响所有共用该资源的球员，不能当作正式绑定**）。
   - **独立绑定候选**：克隆一个新的脸部资源包（新包名/新 ID），只让大罗的外观记录指向它。需要 B3/B4 找到"球员 → 脸部包"的映射规则后才能落地。
5. 全部产物独立回读、差分、生成清单与回退包，交给主控 Claude 集成，再给你实机验收清单。
